API Forge Documentation

Welcome to API Forge! This guide will help you understand how to configure mock servers, create REST endpoints, and simulate network delays for your frontend development.

Getting Started

API Forge is a local-first mocking tool designed to decouple frontend development from backend readiness. By configuring virtual servers and endpoints, you can simulate API responses without writing any backend code.

Core Concept

In API Forge, Endpoints belong to Servers. You must select an active server from the Dashboard to view or create endpoints for it.

Mock Servers

A Mock Server acts as a virtual host container. Instead of having all your mock endpoints jumbled together, you can separate them by project or environment (e.g., Staging vs Production).

Creating a Server

Navigate to the Mock Servers tab. Click "New Server" and define a name, port (e.g., 3000), and a base prefix (e.g., `/api/v1`).

Switching Servers

From the Dashboard sidebar, use the "Active Server" dropdown to switch your context. Only endpoints belonging to the active server will be displayed.

Creating Endpoints

Once a server is active, you can define REST endpoints. Click the "+ New Endpoint" button from the Dashboard to open the Endpoint Builder.

1

Define the Route

Specify the HTTP method (GET, POST, PUT, DELETE) and the specific path (e.g., /users).

2

Set Status & Delay

Simulate real-world conditions by setting a custom HTTP status code (like 404 for testing errors) and a network delay in milliseconds.

3

Provide JSON Payload

Paste the exact JSON response body you want this endpoint to return to your application.

Test Simulator

The Dashboard acts as a Master-Detail interface. Selecting an endpoint from the sidebar opens it in the Simulator.

Simulator Console

By clicking Send Test Request, API Forge visually demonstrates exactly how your frontend will experience the API call. It will render a loading skeleton for the duration of the configured delay before finally presenting the JSON payload and status badge.
